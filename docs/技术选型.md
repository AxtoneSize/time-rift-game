# 《穿越找茬》技术选型与架构说明

> 版本 v0.1.0 · 2026-10-27 · 对应策划方案 v2.0 §10「交付开发规格」
> 本文档回答：为什么这么选、工程怎么组织、后续怎么扩展到 120 关。

---

## 1. 技术选型结论

| 维度 | 选择 | 理由 |
|---|---|---|
| 引擎 | **原生 Canvas 2D，零引擎**（首版/M2 阶段） | ① 玩法是「一张图 + 点击判定」，引擎能力（物理、骨骼、粒子）用不上；② 主包体积最小（<1MB，含图 443KB），对 4MB 限制毫无压力；③ 零构建、零依赖，1-2 人团队维护成本最低；④ 策划方案 §10 给的 Cocos/Laya 选项留给 M3 之后：一旦需要骨骼动画、Spine、复杂粒子或性能瓶颈，再整体迁移 |
| 渲染 | Canvas 2D API + 750×1624 逻辑坐标基准 | 与 UI 设计 v1.2 的设计稿基准一致；DPR 物理像素渲染避免发虚 |
| 语言 | ES5 语法 + IIFE 全局模块（CommonJS 兼容） | 小游戏 `require()` 与浏览器 `<script>` 同源加载，两端零分叉 |
| 架构 | 场景管理器（Home/Game）+ 弹层栈（Overlay Stack）+ 模块化单文件职责 | 弹层（暂停/结算/模拟广告/图鉴/设置）统一模态路由，触摸先弹层后场景 |
| 美术 | AI 生成插画（§6.2 提示词模板）→ 人工标记坐标 → JPEG 入库 | 第 1 关场景图 1536×1024 生成，裁水印后 1521×973，443KB |
| 音频 | WebAudio 运行时合成（零音频文件） | 找出「叮」连击升调 / 误点闷响 / 心跳 / 通关 jingle 全部振荡器合成，不占包体；`wx.createWebAudioContext` + 浏览器 AudioContext 双通道降级 |
| 变现 | 激励视频 `wx.createRewardedVideoAd` 封装 + 游戏内模拟广告兜底 | 广告位未配置/拉起失败/预览环境一律走模拟弹层，满足提审项「无填充有兜底」 |
| 存档 | `wx.setStorageSync` 本地存档 | 金币/提示道具/星级/图鉴进度；好友榜等云能力按 §10 留到后期 |
| 测试 | Node 无头冒烟测试（wx/canvas 桩）+ 关卡数据校验脚本 | 不开开发者工具即可回归全流程；关卡量产时先过校验脚本 |

### 与策划方案 §10 逐项对照

| §10 要求 | 实现 |
|---|---|
| 技术选型：Cocos 或 Laya | M2 首版选原生 Canvas（理由见上），迁移决策点写在 §4 |
| 关卡数据结构 | `js/level-data.js` 完全按 §10 JSON 结构（levelId/chapterId/sceneImage/timer/anachronisms{x,y,rx,ry}/decoys/starThresholds），另加 isTutorial、lore |
| 广告接口 ×5 位埋点 | `js/ads.js` 按 adUnitId 槽位封装（freeHint/extraTime/doubleCoin/dailyGift/codexCard） |
| 存档 | `js/storage.js` |
| 校验脚本 | `tools/validate_levels.js`（画幅内/三区分散/热区重叠/同章重复） |
| M2 验收：与 demo 体验一致 | `tools/smoke_test.js` 40 项断言覆盖核心循环 |

## 2. 工程结构

```
time-rift-game/
├── game.js                  # 小游戏入口（require 链，顺序即依赖序）
├── game.json                # 竖屏、全屏
├── project.config.json      # 开发者工具配置（docs/tools/preview 已加入发包忽略）
├── index.html               # 浏览器预览版入口（纯静态零构建，手机可玩）
├── js/
│   ├── platform.js          # 平台适配：小游戏原生 wx 直通；浏览器注入 wx mock
│   ├── config.js            # 数值与色彩令牌集中配置（改数值只动这里）
│   ├── level-data.js        # 关卡数据（§10 结构）
│   ├── ui.js                # 绘制组件库：玻璃浮层/琥珀按钮/金圈脉冲/奶油纸弹窗
│   ├── audio.js             # WebAudio 音效合成
│   ├── storage.js           # 本地存档
│   ├── ads.js               # 激励视频封装 + 兜底路由
│   ├── mock-ad.js           # 模拟广告弹层
│   ├── overlays.js          # 设置 / 时光图鉴弹层 + 弹层栈管理
│   ├── scene-home.js        # S1 主菜单（满屏插画沉浸版）
│   ├── scene-game.js        # S4 关卡内玩法 + 暂停/续时/结算弹层
│   └── main.js              # 视口适配、图片加载、场景管理器、主循环
├── assets/scenes/scene_xiaomaibu.jpg   # 第1关场景图（443KB）
├── tools/
│   ├── validate_levels.js   # 关卡数据校验（量产必过）
│   ├── smoke_test.js        # 无头冒烟测试（40 断言）
│   └── prep_scene.py        # 场景图预处理（裁水印/压缩）
└── docs/技术选型.md
```

**双端同源原理**：所有业务代码只面向 `wx.*` 与 Canvas 编程。`platform.js` 在浏览器里注入最小 wx mock（触摸/存储/系统信息/振动/图片），在小游戏里是空操作。同一份 `js/` 同时服务 `game.js`（require）与 `index.html`（script 标签）。

## 3. 关键适配实现

| 项 | 实现 |
|---|---|
| 设计基准 | 750 逻辑宽固定，逻辑高随设备自适应（VH = 屏高/缩放）；UI 上下锚定、场景卡片居中 |
| DPR | canvas 物理像素 = 窗口 × min(devicePixelRatio, 2)，一套逻辑坐标绘制 |
| 安全区 | `safeArea.top/bottom` 换算为逻辑值，HUD 与底部按钮避让 |
| 触摸 | 只处理 touch（预览版 mouse 仅在桌面兜底），按下/抬起配对判定，滑动超过 40px 不算点击 |
| 点击判定 | 穿越物椭圆热区（图像素坐标）→ cover/contain 逆变换回图像空间做 `((dx/rx)² + (dy/ry)²) ≤ 1` 检测 |
| 场景展示 | 游戏内 contain 完整展示（保证穿越物全可见），底图 cover 压暗做环境光 |
| 椭圆兼容 | `ctx.ellipse` 改用「平移+缩放+arc」实现，规避低端机兼容问题 |

## 4. 后续迁移与扩展决策点

1. **换引擎时机**：出现以下任一情况再迁 Cocos Creator——需要骨骼/Spine 动画、复杂粒子、跨场景资源管理成为痛点、低端机帧率不达标且无法优化。当前架构中场景/弹层/数据的职责划分可平移到 Cocos 的组件模型。
2. **关卡量产**：每关只需 ① 场景图 ② 在 `level-data.js` 追加一条数据（先出图 → 看图标坐标 → 跑 `node tools/validate_levels.js` → 过 QA 清单）。100 关后按 §5 转「场景库 × 穿越物组合」程序化配置。
3. **广告上线**：在 `config.js` 的 `adUnitIds` 填入 5 个真实广告位 ID，代码无需改动；无填充自动兜底。
4. **需核对官方文档的 API**（开发时已做特性检测，提审前按文档复核版本基线）：`wx.createWebAudioContext`、`wx.createImage`、`wx.createRewardedVideoAd`、`wx.shareAppMessage`。
5. **分包**：当前主包 <1MB；场景图超过 8-10 张后按章节走 `subpackages` 分包加载（game.json 配置 + 分包内图片路径）。

## 5. 已知限制（v0.1.0）

- 仅 1 关；主页「章节选择/关卡选择/每日任务」等入口未做（避免空占位，提审红线）
- 音效为合成音，量产前替换为授权音效库（§6.4）
- 分享：结算页暂未放主动分享按钮（`wx.shareAppMessage` 已可用，接入只需一个按钮）
- iOS 真机、微信开发者工具真机预览尚未实测（需开发者工具 + 真机环境）
